## Client release 0.1.83

- Use `ohmyhost secret form create` and `ohmyhost secret form status` to collect application secrets through a private form. The web page receives the values directly. [Runtime secrets](/secrets)
- A managed pnpm build can resolve newly added packages while preserving the saved lockfile's existing pins. The platform checks TanStack Start's generated Worker output and the complete Next.js Worker module budget, including scheduled functions. [TanStack Start](/frameworks/tanstack) · [Next.js](/frameworks/nextjs)
- Deployment plans give more specific errors for GitHub source problems. Operation status can identify the provider verification step, and terminal failures point to the relevant migration or packaged artifact when that information is available. [Deployment status](/status) · [Troubleshooting](/troubleshooting)
- A project operator can give its private Cloudflare DNS authorization link to the zone's DNS administrator. Newly deployed apps built with customer runtime 0.1.83 make managed mail and file requests with manual redirects. [Domains](/domains) · [Email](/email) · [Files](/files)

## Client release 0.1.82

Apps using managed PostgreSQL can use the private database binding to hash and verify app-owned passwords. New hashes use Better Auth scrypt. Existing stock Better Auth hashes and supported 160,000-iteration PBKDF2-v1 records can be verified in place. See [application authentication](/application-auth#app-owned-password-hashing) for setup, password processing location and reset retries.

When the provider ends a customer Worker invocation for a resource limit, the gateway returns HTTP 503. A confirmed CPU termination can appear as `CPU_LIMIT_EXCEEDED` in deployment logs. See [limits](/limits).

## Client release 0.1.81 (November 24, 2026)

Install the matching CLI and MCP. No command or tool was removed:

```sh
npm install --global @amerged/ohmyhost-cli@0.1.81 @amerged/ohmyhost-mcp@0.1.81
```

- **Replace functions and triggers in a migration.** A later migration can now change the body of a function or the definition of a trigger that an earlier applied migration created, with `CREATE OR REPLACE FUNCTION` or `CREATE OR REPLACE TRIGGER`, in the `public` or `private` schema. The deployment plan, `ohmyhost init --dry-run` (`migrationEffects`) and the promotion plan list each replacement before anything runs, and a refused replacement rolls back the pending files. Dependent constraints, indexes, defaults and policies are refused. [Replace a function or trigger](/migrations#replace-a-function-or-trigger).
- **Temporary database access names its network needs.** The Skills now say that the credential needs outbound TLS and WebSocket access to the `websocket_url` host on port 443, and that direct PostgreSQL TCP on port 5432 is unavailable. [Connect with psql](/database#connect-with-psql-or-a-sql-client).

## Client release 0.1.80 (November 24, 2026)

Install the matching CLI and MCP. No command or tool was removed:

```sh
npm install --global @amerged/ohmyhost-cli@0.1.80 @amerged/ohmyhost-mcp@0.1.80
```

- **Database migrations from chat.** `database_migrate` (MCP), `ohmyhost database migrate` and `POST /v1/projects/{project_id}/database/migrations` (`migrateDatabase`) apply the migration files of one saved version to the Dev or Prod database of a project and create that database first when the environment has none. Your assistant asks where to apply them: a Free workspace and a project without a Dev site apply to Prod; with a Dev site you choose Dev only or Dev and Prod. A refused file is named in the error; add a new migration file instead of editing one that was applied. The new error codes are listed in the [error codes](/troubleshooting#error-codes), for example [`database_migrate_paid_required`](/errors/database-migrate-paid-required).
- **The preview shows the app, saving works after publishing.** The preview link now arrives at once, without waiting for the database. A preview shows the app only and does not save data; saving works once the app is published (the Dev site on Paid, the live site on Free) after the database changes were applied. [Live previews](/previews).
- **Large saves.** Saving a version with many or large files to a managed project no longer fails.
- **Clearer refusal to switch a managed project to GitHub.** Linking a managed project to GitHub answers `409 source_switch_unsupported` with the next step instead of a generic 503. [`source_switch_unsupported`](/errors/source-switch-unsupported).
- **Starter runtime dependency.** The `vite-react` starter now lists `@ohmyhost/customer-runtime` (an alias for `@amerged/ohmyhost-runtime`) in its dependencies, so publishing an app that uses the database clients works from a chat without installing anything.

## Client release 0.1.79 (November 23, 2026)

Install the matching CLI and MCP. No command or tool was removed:

```sh
npm install --global @amerged/ohmyhost-cli@0.1.79 @amerged/ohmyhost-mcp@0.1.79
```

- **Deletion progress in chat clients.** While a project is being deleted, `operation_get` and `project_status` keep answering: the operation reports `queued` or `running` with its work progress and ends as `succeeded`, and the project reports the lifecycle `deleting` instead of a not-found error. A deletion with many files can take about ten minutes. Writes to a deleting project are still refused.
- **Damaged preview link.** A preview link that is incomplete or was changed in transit now answers 404 with a short page that says the link is incomplete or damaged and asks you to have your assistant give you the preview link again; non-browser requests receive the same sentence as plain text.
- **Secret input requests in the API reference.** The [API reference](/api) now lists `createSecretInputRequest` and `getSecretInputRequest` (`/v1/projects/{project_id}/environments/{environment_id}/secret-input-requests`), the protected form that lets a person enter a secret value without it passing through a chat.

## Client release 0.1.59 (November 16, 2026)

## Client release 0.1.48 (November 3, 2026)

- **LLM cost fallback.** Chat and Responses use a USD 0.01 cost only when the answered call has no usable recorded trace cost after bounded lookup, or no usable trace id. Actual cost always takes priority, including zero and amounts below USD 0.01. The unchanged rate-card factor applies to the selected cost; operator records mark fallback use, and there is no automatic later correction. Other unmeasured AI routes still settle at zero. [AI billing rules](/ai#credits-and-budgets).

## Client release 0.1.45 (November 1, 2026)

Install the matching CLI and MCP. Clients older than 0.1.45 do not have the `database watch` commands and tools:

```sh
npm install --global @amerged/ohmyhost-cli@0.1.45 @amerged/ohmyhost-mcp@0.1.45
```

- **Table watches.** A watch publishes the insert, update and delete changes of one table's listed columns as signed `data.<topic>` webhook events. `ohmyhost database watch create|list|delete`, MCP `database_watch_create|list|delete` and the REST watch routes manage them. [Table watches](/database#table-watches).
- **Operation lookup.** `ohmyhost operation get` and every CLI `--wait`, and MCP `operation_get`, find existing deployment, source and project operations again. [Read deployment status](/status).

- **Deployment faults.** A fault that stopped deployments before the build started is fixed. [Diagnose a deployment](/troubleshooting).
- **Database dumps.** Customer database dumps leave out the platform event schema. [Export your database](/backups).
- **Token retries.** After a rejection, `ohmyhost token create` can be run again under the same idempotency key; the stale rejection is replaced. [Login and API tokens](/login-tokens).

## Client release 0.1.41 (October 30, 2026)

**Breaking for clients older than 0.1.41 that read credits or usage.** Update CLI and MCP together before you read either:

```sh
npm install --global @amerged/ohmyhost-cli@0.1.41 @amerged/ohmyhost-mcp@0.1.41
```

- **Usage report.** `GET /v1/organizations/{organization_id}/credit-usage`, `ohmyhost credits usage` and MCP `organization_usage_get` return the billed charges of the last up to 14 UTC days grouped by day, project and meter, plus what each project has used so far this UTC month. The `month` and `cursor` inputs are removed (CLI `--month` and `--cursor`, MCP `month` and `cursor`); older days are not kept. [Understand usage](/usage).
- **Credit account.** `GET /v1/organizations/{organization_id}/credits` and `ohmyhost credits balance` no longer return `spent_micros`, `expired_micros` or `platform_overrun_micros`. `available_micros` is the monthly credit plus the one-time credit minus reservations, next to `reserved_micros`, `grace_started_at`, `grace_expires_at`, `active_meters` and `rate_cards`. In `ohmyhost credits account`, `paid_until` is the end of the paid coverage and includes the fourteen-day renewal grace of a Stripe subscription.
- **Credits do not expire.** Top-up, auto-recharge, bonus and referral credits never expire, also after a downgrade to Free; before, top-ups ended with the Paid coverage. Monthly credits (200 on Free, 1,000 on Paid) still end with their period and are spent first. Only effective Paid workspaces can buy top-ups or enable auto-recharge. [Credit prices](/pricing) · [Billing](/billing).
- **Databases run on PGCF.** Customer PostgreSQL databases run on [PGCF](https://github.com/amerged-org/cloudflare-postgres), the open-source PostgreSQL platform behind ohmyho.st; the previous database provider is retired. Every new access credential is a PGCF credential over WSS, and older entries in `database access list` stay `expired` or `revoked`. [Postgres queries, writes and compute](/database).

## Current clients

[Current release](https://ohmyho.st/client-release.json) identifies the active version and immutable manifest. The manifest lists CLI, MCP, SDK and runtime archives with SHA-256 hashes. Only the current release is served; older release URLs return 404.

## Account workflows

Client release 0.1.34 adds the current account email and workspace names beside their IDs to `GET /v1/me`, CLI `whoami` and local/remote MCP `identity_get`. User API tokens report their owner's email; machine-to-machine credentials report null. Upgrade CLI and MCP together with the current release when checking the signed-in account. [Current account details](/login-tokens#check-the-current-account).

One computer can keep several saved logins, each bound to one user/organization. Select --profile-name, MCP `profile_name` or `OHMYHOST_PROFILE`; the first legacy-profile upgrade needs network access. After another login is saved, ambiguity needs an explicit choice. organization use binds only an unbound login; use login --organization ID for another workspace. [Several accounts](/login-tokens#several-accounts-on-one-computer).

The portal provides projects, profile, Billing, Usage and user API Tokens. New keys remain valid until revoked; existing keys keep their recorded expiry. Granted Paid features are separate from Stripe subscriptions and monthly credit grants.

Task guides cover GitHub deployments into Dev or direct Prod, promotion/rollback, protected/public Dev links, immutable US/EU region, chosen project addresses, PostgreSQL and time-bound SQL access, private files, schedules, domains/mail, usage/budgets, project context, feedback and encrypted SQL exports. Read each task guide for its current limits and permissions.

## Interface changes

The accompanying release adds guarded Dev/Prod data assignment changes without copying records, a fresh file namespace after Dev reset, bulk `readMany`/`deleteMany` and explicit browser-origin declarations. Keep CLI/MCP/runtime together and read the linked current-release manifest; older clients can reject changed response shapes. These documentation changes do not establish a live application's behavior: verify its required flows after deploying.
