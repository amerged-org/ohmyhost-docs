## Client release 0.1.43 (October 31, 2026)

**Breaking for clients older than 0.1.43 that read the credit balance.** Update CLI and MCP together:

```sh
npm install --global @amerged/ohmyhost-cli@0.1.43 @amerged/ohmyhost-mcp@0.1.43
```

- **Credit balance only.** `GET /v1/organizations/{organization_id}/credits` and `ohmyhost credits balance` return `available_micros`, `reserved_micros`, `grace_started_at` and `grace_expires_at`. `active_meters` and `rate_cards` are removed; an older CLI rejects the answer with `response_contract_invalid`. [Understand usage](/usage).

## Client release 0.1.42 (October 31, 2026)

- **Database webhooks, schedules and executions.** `ohmyhost database webhook`, `database schedule` and `database executions` (and the matching MCP tools and REST routes) manage signed HTTPS webhooks for database state changes, scheduled SQL and execution counters of a Dev or Prod database. [Webhooks, schedules and executions](/database).

## Client release 0.1.41 (October 30, 2026)

**Breaking for clients older than 0.1.41 that read credits or usage.** Update CLI and MCP together before you read either:

```sh
npm install --global @amerged/ohmyhost-cli@0.1.41 @amerged/ohmyhost-mcp@0.1.41
```

- **Usage report.** `GET /v1/organizations/{organization_id}/credit-usage`, `ohmyhost credits usage` and MCP `organization_usage_get` return the billed charges of the last up to 14 UTC days grouped by day, project and meter, plus what each project has used so far this UTC month. The `month` and `cursor` inputs are removed (CLI `--month` and `--cursor`, MCP `month` and `cursor`); older days are not kept. [Understand usage](/usage).
- **Credit account.** `GET /v1/organizations/{organization_id}/credits` and `ohmyhost credits balance` no longer return `spent_micros`, `expired_micros` or `platform_overrun_micros`. `available_micros` is the monthly credit plus the one-time credit minus reservations, next to `reserved_micros`, `grace_started_at`, `grace_expires_at`, `active_meters` and `rate_cards`. In `ohmyhost credits account`, `paid_until` is the end of the paid coverage and includes the fourteen-day renewal grace of a Stripe subscription.
- **Credits do not expire.** Top-up, auto-recharge, bonus and referral credits never expire, also after a downgrade to Free; before, top-ups ended with the Paid coverage. Monthly credits (200 on Free, 1,000 on Paid) still end with their period and are spent first. Only effective Paid workspaces can buy top-ups or enable auto-recharge. [Credit prices](/pricing) · [Billing](/billing).
- **Databases run on PGCF.** Customer PostgreSQL databases run on [PGCF](https://github.com/amerged-org/cloudflare-postgres), the open-source PostgreSQL platform behind ohmyho.st; the previous database provider is retired. Every new access credential is a PGCF credential over WSS, and older entries in `database access list` stay `expired` or `revoked`. [Postgres queries, writes and compute](/database).

## Current clients

[Current release](https://ohmyho.st/client-release.json) identifies the active version and immutable manifest. The manifest lists CLI, MCP, SDK and runtime archives with SHA-256 hashes. Only the current release is served; older release URLs return 404.

## Account workflows

Client release 0.1.34 adds the current account email and workspace names beside their IDs to `GET /v1/me`, CLI `whoami` and local/remote MCP `identity_get`. User API tokens report their owner's email; machine-to-machine credentials report null. Upgrade CLI and MCP together with the current release when checking the signed-in account. [Current account details](/login-tokens#check-the-current-account).

One computer can keep several saved logins, each bound to one user/organization. Select --profile-name, MCP `profile_name` or `OHMYHOST_PROFILE`; the first legacy-profile upgrade needs network access. After another login is saved, ambiguity needs an explicit choice. organization use binds only an unbound login; use login --organization ID for another workspace. [Several accounts](/login-tokens#several-accounts-on-one-computer).

The portal provides projects, profile, Billing, Usage and user API Tokens. New keys remain valid until revoked; existing keys keep their recorded expiry. Granted Paid features are separate from Stripe subscriptions and monthly credit grants.

Task guides cover GitHub deployments into Dev or direct Prod, promotion/rollback, protected/public Dev links, immutable US/EU region, chosen project addresses, PostgreSQL and time-bound SQL access, private files, schedules, domains/mail, usage/budgets, project context, feedback and encrypted SQL exports. Read each task guide for its current limits and permissions.

## Interface changes

The accompanying release adds guarded Dev/Prod data assignment changes without copying records, a fresh file namespace after Dev reset, bulk `readMany`/`deleteMany` and explicit browser-origin declarations. Keep CLI/MCP/runtime together and read the linked current-release manifest; older clients can reject changed response shapes. These documentation changes do not establish a live application's behavior: verify its required flows after deploying.
