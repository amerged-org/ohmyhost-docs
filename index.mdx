> Read https://ohmyho.st/llms.txt and https://ohmyho.st/skills/ohmyhost-get-started/SKILL.md. Connect this agent to ohmyho.st and deploy this app using only the capabilities it needs. Keep its existing source binding, or choose managed source or GitHub if it is unbound. Follow the deployment Skill, preserve my project decisions and verify the app.

Your agent tells you what it needs, connects the intended account, reuses your workspace and inspects the selected app before creating anything. A connected chat uses managed OAuth; a terminal agent can reuse its saved login. Signing up is open. [Sources and versions](/sources) work across chats without creating another app.

## Start with what your app needs

A public Vite app can start with hosting alone. Add Postgres, [files](/files), runtime secrets or [functions and crons](/functions) when the application needs them. Transactional email needs Paid; a custom domain needs Paid or the opt-in [ohmyho.st flag](/domains). Keep your application's own authentication provider.

## Your first result

The agent follows the accepted deployment and verifies the real application. Dev is protected by default: ask your agent for the reusable Dev share link, or choose public Dev when the project is created. Publish to Prod after you are ready.

- [First deployment](/quickstart): managed source and GitHub workflows.
- [Connect MCP](/agents/mcp): setup for your agent.
- [CLI](/cli): install and run the commands yourself.
- [API](/api): use your account token from another tool.

## Come back with a question

“Which project used the most credits?” “Is my domain ready?” “Export my database.” Your agent reads the saved [project context](/project-context) and uses the same account access as the [portal](https://app.ohmyho.st/).
