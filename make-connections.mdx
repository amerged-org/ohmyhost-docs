---
title: "Connect Make"
description: "Connect Make once in your workspace and ask your agent to find the connection you want to use."
---

Connect Make once in your ohmyho.st workspace. Your agent can use that authorization to find the Make connections available to you across projects in the workspace. Credentials stay in the connection service.

## Connect your account

Open [Connections](https://app.ohmyho.st/connections) in the workspace you want to use and select **Connect Make**. Sign in if prompted, review the permissions on Make’s consent screen and approve access. When the portal shows that Make is connected, return to your agent or start a new chat.

If you start from chat, have your agent use `integration_connection_list` to look for your active workspace grant. It can create a protected consent link with `integration_connection_begin` when you need to connect. Open that link as the same ohmyho.st user who requested it and confirm that you want to connect Make. If a manual save is needed after Make returns, select **Save connection**.

To start from the CLI, use your saved login and workspace.

```sh
ohmyhost connection begin \
  --organization ORGANIZATION_ULID \
  --idempotency-key make-connect-1 \
  --profile-name PROFILE_NAME --json
```

Open the returned URL privately and approve access on Make. Use the request ID to check the handoff.

```sh
ohmyhost connection status \
  --organization ORGANIZATION_ULID \
  --request REQUEST_ID \
  --profile-name PROFILE_NAME --json
```

`consumed` means the portal accepted the link. Check `connection list` for an `active` grant to verify that Make is connected.

## Find a connection in chat

Copy the prompt from the portal into your chat.

> Help me connect a SaaS tool to my application using Make. Ask me which tool I want to use, then find its connection.

Your agent reuses your active workspace grant. It uses `integration_connection_discover` to list Make organizations, then teams within each relevant organization, then connection names and IDs in those teams. It can use an organization or team you already named to narrow the search. If it finds one clear match, it can identify the connection right away. When several match, it can show their names and teams so you can choose. If the names do not identify the integration, tell the agent the connection name you see in Make.

Discovery works before you have a project. It reads connection metadata. Running Make Endpoints for CRM data or actions such as sending email is currently unavailable.

```sh
ohmyhost connection list \
  --organization ORGANIZATION_ULID \
  --profile-name PROFILE_NAME --json

ohmyhost connection discover \
  --organization ORGANIZATION_ULID \
  --grant GRANT_ULID \
  --profile-name PROFILE_NAME --json
```

Discovery returns organizations first. Repeat it with `--provider-organization ID` to list that organization's teams, then add `--team ID` to inspect the team's connections.

Discovery finds organizations across Make zones and reads team and connection metadata from the selected organization's zone.

Make controls its OAuth token lifetimes. The service refreshes a valid grant as needed. A grant that can no longer refresh requires consent again. The grant persists across portal logins, and access depends on the linking user's current workspace rights.

## Import into a project

Ask for an import when you want to save a connection reference in a particular app. For example, “Import that connection into the dev environment of my support app.” The agent can reuse the project and environment from your request or chat context and ask if the destination is unclear. You can import the same connection into another authorized project in your workspace using the same Make grant.

Use `integration_connection_import` in chat or the following CLI command with IDs from discovery and project context.

```sh
ohmyhost connection import \
  --organization ORGANIZATION_ULID \
  --grant GRANT_ULID \
  --project PROJECT_ULID \
  --environment ENVIRONMENT_ULID \
  --provider-organization MAKE_ORGANIZATION_ID \
  --team TEAM_ID \
  --connection CONNECTION_ID \
  --idempotency-key make-import-1 \
  --profile-name PROFILE_NAME --json
```

## Older clients

Version 0.1.62 clients pass project and environment together when beginning a connection or discovering its catalog. Those paired parameters remain supported for the earlier project-scoped flow. Use a current client for workspace connection, discovery and import; a project-scoped connection does not automatically become a workspace grant.

## Disconnect

Use `integration_connection_disconnect`, or the CLI's `connection disconnect` command with its required confirmation. Disconnect immediately blocks local use and requests upstream revocation. It does not delete the third-party connections stored in your Make team. If revocation is still pending, retain that reported state and follow it rather than treating it as confirmed.

```sh
ohmyhost connection disconnect \
  --organization ORGANIZATION_ULID \
  --grant GRANT_ULID \
  --idempotency-key make-disconnect-1 \
  --yes --profile-name PROFILE_NAME --json
```

A refused or unavailable connection needs its reported account, permission or provider issue resolved. Repeating consent or changing client transport does not expand your access. [Sign-in and account selection](/login-tokens) explains saved logins and current workspace rights.
