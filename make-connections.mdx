---
title: "Connect Make"
description: "Link your Make account to a workspace, discover connections and import one into a project."
---

Connect your Make account to an ohmyho.st workspace. The grant belongs to your user and the selected workspace; you do not need to choose a project to connect or discover. Complete the protected portal handoff as the same person, then review and approve Make's consent screen. Your provider tokens stay in the connection service; responses to your agent contain safe status and discovery metadata.

<Info>
This integration supports account linking, read-only discovery and explicit project imports where available. Running app actions through Make Endpoints remains unavailable until it is separately qualified. Availability is reported by the connected environment.
</Info>

## Connect your account

Ask your agent to connect Make for the selected workspace. It uses `integration_connection_begin`, opens the returned protected link for you, and follows `integration_connection_status` after you finish consent. Both your initiating login and portal login must identify the same person. Current workspace role and explicit credential restrictions still apply.

For the CLI, select your saved login and workspace:

```sh
ohmyhost connection begin \
  --organization ORGANIZATION_ULID \
  --idempotency-key make-connect-1 \
  --profile-name PROFILE_NAME --json
```

Open the returned URL privately and complete the two consent steps. Retain the returned request ID to check completion:

```sh
ohmyhost connection status \
  --organization ORGANIZATION_ULID \
  --request REQUEST_ID \
  --profile-name PROFILE_NAME --json
```

This status tracks the protected handoff: `consumed` means the portal accepted it, even if Make consent has not finished. After completing consent and the final portal confirmation, use `connection list` to check for an `active` grant. Neither response returns an access token or refresh token. A human session's selected workspace is context; current target-workspace access and any explicit restrictions decide whether the request is allowed. An API key remains limited to its recorded workspace and permissions.

## Inspect connections

`integration_connection_list` lists your permitted grants. Use `integration_connection_discover` with the selected workspace grant to inspect Make organizations, teams and existing connections. Select only IDs returned by that discovery. This operation reads metadata and does not run scenarios, send email or change CRM records.

```sh
ohmyhost connection list \
  --organization ORGANIZATION_ULID \
  --profile-name PROFILE_NAME --json

ohmyhost connection discover \
  --organization ORGANIZATION_ULID \
  --grant GRANT_ULID \
  --profile-name PROFILE_NAME --json
```

Discovery returns organizations first. Repeat it with `--provider-organization ID` to list that organization's teams, then add `--team ID` to inspect the team's connections.

Your app's hosting region does not choose Make's data region. Organization discovery reads across Make zones; team and connection metadata are read from the selected organization's zone.

Make controls its OAuth token lifetimes. The service refreshes a valid grant as needed; a revoked or expired grant requires consent again. Ordinary portal logout does not disconnect a successfully linked account, while losing the linking user's workspace rights suspends use.

## Import into a project

After discovery, choose the Make organization, team and connection, then select the destination project and environment. Import records that explicit selection; it does not run a Make action. Ask your agent to use `integration_connection_import`, or use the CLI with IDs returned by discovery and project context:

```sh
ohmyhost connection import \
  --organization ORGANIZATION_ULID \
  --grant GRANT_ULID \
  --project PROJECT_ULID \
  --environment ENVIRONMENT_ULID \
  --provider-organization MAKE_ORGANIZATION_ID \
  --team TEAM_ID \
  --connection CONNECTION_ID \
  --idempotency-key make-import-1 \
  --profile-name PROFILE_NAME --json
```

## Use the portal

Sign in to the portal, select your workspace under Projects and open **Connections**. Connect Make, then select an active grant, Make organization and team. Choose a connection and destination project and environment to import it. The portal offers only the choices available to your account.

## Older clients

Version 0.1.62 clients pass project and environment together when beginning a connection or discovering its catalog. Those paired parameters remain supported for the earlier project-scoped flow. Use a current client for workspace connection, discovery and import; a project-scoped connection does not automatically become a workspace grant.

## Disconnect

Use `integration_connection_disconnect`, or the CLI's `connection disconnect` command with its required confirmation. Disconnect immediately blocks local use and requests upstream revocation. It does not delete the third-party connections stored in your Make team. If revocation is still pending, retain that reported state and follow it rather than treating it as confirmed.

```sh
ohmyhost connection disconnect \
  --organization ORGANIZATION_ULID \
  --grant GRANT_ULID \
  --idempotency-key make-disconnect-1 \
  --yes --profile-name PROFILE_NAME --json
```

A refused or unavailable connection needs its reported account, permission or provider issue resolved. Repeating consent or changing client transport does not expand your access. [Sign-in and account selection](/login-tokens) explains saved logins and current workspace rights.
