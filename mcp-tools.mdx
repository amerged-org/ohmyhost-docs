## Source tools

[Sources and versions](/sources) explains the source choice, revision guards, save completion and restoration. Read `source_get` before choosing a source. Request `include_binding: true` for connection/generation guards; the default GitHub status view remains unchanged, while managed source is always complete. Preserve the selected project and source.

| Task                             | Tool                                               | Usage                                                                                                                                                                                                                                                        |
| -------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Inspect this computer's checkout | `source_inspect`                                   | Local only; read `directory` without sign-in or uploading.                                                                                                                                                                                                   |
| Save current local files         | `source_publish`                                   | Local only; `initialize`, `commit` or an explicitly requested GitHub-to-managed `switch`. Keep the connection/generation and original key. Omit `expected_commit_sha` only when this directory has its own confirmed base from successful local publication. |
| Finish an accepted local save    | `source_publish_complete`                          | Local only; same `project_id`, `directory`, optional `operation_id` and login. Confirms the exact version and stores its local base; uploads no files.                                                                                                       |
| Observe the upload receipt       | `source_upload`                                    | Local and remote; read `project_id` and `operation_id`. Require operation success and a committed receipt; sealed is not confirmation.                                                                                                                       |
| Create a managed template        | `source_initialize`                                | Unbound source only; choose `empty` or `vite-react`, current `expected_source_generation` and a saved key. Do not duplicate pending project initialization.                                                                                                  |
| Read saved files                 | `source_files`, `source_file`                      | Local `source_files` lists the manifest; `source_file` reads a path. Remote `source_files` also accepts `path`. Use the actual connected schema.                                                                                                             |
| Save a file batch                | `source_changes`                                   | Current generation and parent commit; each change supplies one text/base64 content field and preserves the executable flag.                                                                                                                                  |
| Inspect and restore history      | `source_versions`, `source_diff`, `source_restore` | Restore creates a new version; it neither deploys nor reverts database data.                                                                                                                                                                                 |

For a complete native-chat snapshot, use remote `source_upload_prepare` and `source_blob_put`, then `source_upload_commit` for initialize/commit or `source_switch` for an explicitly requested GitHub-to-managed switch. `source_blob_put` computes hashes and byte lengths from real file contents; keep its exact receipts for every file, including unchanged retained files. The final manifest must match all receipts from this upload. Observe the original operation with `source_upload`; these tools neither read a local directory nor start deployment. [Complete-tree flow](/sources#save-a-complete-tree-in-chat).

MCP text reads default to `content_text` with `encoding: "utf8"`, with a base64 fallback for binary files. `source_changes` accepts exactly one `content_text` or `content_base64` per path; `content_base64: null` deletes the file. REST uses base64. The [editing example](/sources#develop-in-a-connected-chat) includes the complete argument shape.

The generated catalogue above is the local product server. Remote OAuth clients discover their own tools through `tools/list`; local directory tools cannot operate inside a native chat without a local filesystem. Connection and publishing permissions are described in [MCP setup](/agents/mcp).
