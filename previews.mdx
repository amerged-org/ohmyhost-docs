title: "Live previews"
description: "Open a preview that lasts 24 hours and see saved source changes through your framework's development server."
---

A live preview is a private link to your app's development server and is available on every plan. Open it after saving a version, before publishing. Save a version through [managed source](/sources), or push to the selected [GitHub branch](/github), to update the same awake preview. Code changes use the framework's hot reload. Package, lockfile or runtime-configuration changes can restart its server.

The [Dev site](/environments#choose-who-can-open-dev) is a Paid deployment for testing. The [live site](/environments#deploy-to-prod) is your Prod deployment and serves the version you published.

Cloudflare selects the location of preview compute; the project region selects its data services.

Choose the project environment explicitly. A Dev preview uses Dev data; a Prod preview uses Prod data, including when you write through the app. Free projects have a Prod preview. Paid projects can have a separate Dev preview and Prod preview.

## Open the preview

Use your current [CLI login](/cli) and the intended project. Retrieving or managing its private preview link requires project write permission; viewers use a link shared with them:

```sh
ohmyhost project preview open --project "$PROJECT_ID" --environment prod --json
ohmyhost project preview get --project "$PROJECT_ID" --environment prod --json
```

Open the returned `url` in your browser. `status` is `cold`, `starting`, `ready` or `sleeping`. The URL shows progress while the app starts. `source` identifies the saved version selected for the preview and `applied_source` identifies the version it has applied. Either can be `null`. Share the preview when `ready_to_show` is true, which means the preview is ready and the two version sequences match. The URL stays the same as you save later versions, until the preview expires.

## Preview lifetime

Every preview works for 24 hours after it was created. `expires_at` in the result is that deadline. Activity, saves, stop and rotate never move it. From that moment the link stops working and shows a page that says it is not valid or has expired. The next `preview_open` creates a new preview with a new link, so share only the newest link. Expiry removes the preview's runtime and saved dependencies, never the project environment's database.

## If the preview does not start

When the last start attempt failed, `failure` carries a `code`, `retryable` and a `next_step` that names the file or action that fixes it. A refused name, source or configuration fails the same way for the same saved version, so save the fix first and then open the preview again. When `retry_after_seconds` is set, wait that long before opening it again. For example, `source_migration_filename_noncanonical` lists migration files that must be renamed to `YYYYMMDDHHMMSS_name.sql` ([migrations](/migrations)). A failure of an older saved version is not reported. `failure` is `null` when the preview starts.

Anyone with this URL can view and use the app without a platform login. Share it only with intended viewers. Application login, when configured, still applies.

For an app that uses Native Auth, the preview checks project rollout access before Paid coverage. If it reports `native_auth_launch_unavailable`, ask the project owner to contact [support](/support) with the project ID. If it reports `paid_plan_required` during Native Auth preparation, the owner can check the workspace plan. Once the reported requirement is satisfied, wake the same preview URL. [Native Auth setup](/application-auth#set-up-omh-native-auth).

## Save and continue

Use the normal [source publication flow](/sources#save-current-local-files) for local files, or the connected chat's `source_changes` and `source_upload_*` tools. Follow the save operation until it succeeds. An accepted upload that has not committed yet is not a saved version.

An awake preview applies the accepted files. A sleeping preview keeps the latest target and applies it when opened again. Ordinary code edits retain the running development server; framework hot reload determines which component state can be preserved.

Preview startup does not run customer migrations. Apply an intended schema change through the explicit [migration flow](/migrations). To publish a checked production artifact, continue through the normal [deployment flow](/environments).

## Sleep and reopen

A preview sleeps after ten minutes without meaningful use. An idle tab, hot-reload connection or automatic polling does not keep it awake. Open the URL or use its wake action to continue.

Dependencies are retained until the preview expires. After that, a new preview prepares them again. Sleeping has no compute charge; awake usage follows [the preview rate](/pricing).

A compressed dependency snapshot can be at most 2 GiB. Reduce large dependencies or generated files if the preview exceeds this limit. A snapshot belongs only to the selected project's environment; publication still builds the saved source separately.

## Stop or replace the link

Stop clears the current runtime and dependency cache. A later open prepares the saved source at the same URL until the preview expires:

```sh
ohmyhost project preview stop --project "$PROJECT_ID" --environment prod \
  --idempotency-key "$STOP_REQUEST_KEY" --yes --json
```

Rotate when you want a new link. The old URL stops working and its open connections close. The preview keeps its 24-hour deadline:

```sh
ohmyhost project preview rotate --project "$PROJECT_ID" --environment prod \
  --idempotency-key "$ROTATE_REQUEST_KEY" --yes --json
```

Keep each request's original key after an uncertain response. With managed Native Auth, rotation also invalidates that preview's previous login sessions.

## Loginless preview drafts

Remote MCP clients connected to `https://app.ohmyho.st/mcp` can call `preview_draft` before signing in to show a working prototype immediately.

- **24-hour live preview and 30-day claim archive.** Each draft runs live for 24 hours with a `Save project` bar linking to its `/claim/{token}` page. After 24 hours, the live preview stops and its source and temporary database snapshot move to a 30-day claim archive so the same claim link can still restore the project into an ohmyho.st workspace.
- **Updates require `edit_token`.** Keep the `edit_token` returned on draft creation to push follow-up changes to the same draft; viewers of the preview link cannot edit the code.
- **Optional temporary PostgreSQL (5 tables / 5 MiB).** If `ohmyhost.yaml` enables `database` with canonical migrations, the draft receives an unclaimed temporary PostgreSQL database bounded to 5 user tables and 5 MiB. Larger schemas or writes fail with `guest_database_limit_exceeded` and return `claim_url` so you can claim the draft and unlock full database capacity.
- **Isolated guest tier.** Loginless drafts have outbound runtime egress disabled (`runtime.egress.allow: []`) and do not enable Dev sites, Native Auth, AI, mail, or object storage until claimed into an account workspace.

## Use MCP or REST

Local and remote MCP expose `preview_get`, `preview_open`, `preview_stop` and `preview_rotate`. Pass the project and `environment` returned by your current tool schema. `preview_open` allows up to 20 seconds for wake-up and readiness checks. If it returns while the preview is still starting or applying a version, use `preview_get` to check again.

MCP results can include `next_step` for the agent and `say_to_user` to relay in the user's language. Follow the deploy Skill for when to open the preview, check readiness and share the link. [Deploy Skill](https://ohmyho.st/skills/ohmyhost-deploy/SKILL.md)

The same actions are available through REST.

| Operation                   | Endpoint                                                             |
| --------------------------- | -------------------------------------------------------------------- |
| `getProjectPreview`         | `GET /v1/projects/{project_id}/preview?environment=dev\|prod`        |
| `openProjectPreview`        | `POST /v1/projects/{project_id}/preview?environment=dev\|prod`       |
| `stopProjectPreview`        | `DELETE /v1/projects/{project_id}/preview?environment=dev\|prod`     |
| `rotateProjectPreviewToken` | `POST /v1/projects/{project_id}/preview/token?environment=dev\|prod` |

Use the generated SDK or published API schema for request headers and authorization. Keep capability URLs out of public logs and source files.
