# Run a project-owned container job

Save the source and publish a version with `container_job_version_publish`. Provide the exact saved revision, build context, Dockerfile, argv entry point, maximum run seconds and build spend cap. Use a stable idempotency key on retries. Poll `container_job_version_get` until ready. A PDF converter, for example, can choose its own decoder and system libraries in the image. Build dependencies are separate from invocation.

Obtain a temporary write URL with `container_job_input_upload`, PUT the file with the declared content type and retain the file ID. Store optional JSON parameters the same way with kind `parameters`. Keep temporary grant URLs out of conversations and logs. Call `container_job_quote` with version, ordered input references and runtime cap. Start with the accepted quote ID and maximum microcredits using `container_job_start`. Return the run ID to the customer. `container_job_get` reports state and cost. `container_job_output_download` returns a scoped read URL for a succeeded output after instance termination. `container_job_cancel` asks for a whole-instance stop. Observe the existing run after a timeout.

For server-side app use, allow the environment’s jobs origin (`https://jobs.ohmyho.st` in Production or `https://jobs.dev.ohmyho.st` in Development) in `runtime.egress.allow`. ohmyho.st automatically permits the matching `job-files` transfer origin and injects `OHMYHOST_JOBS_BASE_URL` and a deployment-scoped `OHMYHOST_JOBS_TOKEN` secret into the deployed app; send `Authorization: Bearer ${OHMYHOST_JOBS_TOKEN}` to `${OHMYHOST_JOBS_BASE_URL}/v1/...`. Keep the publisher capability with the project developer. Customer files remain private. These jobs do not have an end-to-end EU residency guarantee. [Program contract and hosting guide](https://docs.ohmyho.st/container-jobs)
