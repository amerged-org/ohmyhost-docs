---
title: "Read deployment status"
description: "Follow the accepted operation and inspect the actual application heads."
---

```sh
ohmyhost project context --project "$PROJECT_ID" --json
ohmyhost project status --project "$PROJECT_ID" --json
ohmyhost operation get "$OPERATION_ID" --json
```

Use the operation ID returned by the mutation. `queued` or `running` means work remains; `succeeded`, `failed` and `cancelled` are terminal. Project status supplies existing environments, a deployment head and URLs.

With client 0.1.57 or newer, `custom_domains` lists this project's production hostnames with `hostname`, `environment` and configuration `state`: `awaiting_deployment`, `pending`, `active` or `deleting`. The hosting `prod_url` remains separate. For DNS and HTTPS readiness, read `ohmyhost domain paid status --project "$PROJECT_ID" --json`; see [Connect a domain](/domains).

A queued operation with `blocking_operation_id` waits for that operation of the same project to end; inspect it instead of submitting again.

With CLI 0.1.66 or newer, list the project's deployments newest first, then inspect the deployment returned by the operation:

```sh
ohmyhost deployment list --project "$PROJECT_ID" --json
ohmyhost deployment get --project "$PROJECT_ID" --deployment "$DEPLOYMENT_ID" --json
```

## Observe the next step

During a deployment, `progress.phase` distinguishes building, publishing and waiting for mail. Follow `progress.next_poll_after_seconds` and the returned suggested action. Read sender or domain status when that dependency is pending.

CLI `--wait` can reach its own timeout without cancelling the server operation. Read the same operation afterward. Never submit another deployment just to get a status update.

For a live event stream:

```sh
ohmyhost logs "$OPERATION_ID" --follow --json
```

During provider verification, `operation_get` reports the last recorded check in `work.step` when available. For example, `verifying_build` means the platform last checked the build artifact, even after compilation finished. Compare `reconciliation.observed_at` across reads of the same operation. A pending attempt carries its `attempt_id` and the next polling interval in its guidance.

MCP `operation_logs` returns a bounded snapshot. Use `operation_get` for current completion rather than assuming the snapshot waits until done.

## Verify success

An operation marked succeeded must still produce the requested outcome. For up to thirty seconds after success, some requests can still reach the previous version or address; recheck before calling a change missing. For protected Dev, open the Owner's Dev share link; for public Dev, open the clean URL. Then test the real application, or read back the changed domain, budget or compute settings. A data-change operation requires the named environment to be redeployed; follow [its assignment plan](/environments#change-data-assignments).
